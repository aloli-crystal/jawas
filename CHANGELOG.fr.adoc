== v0.4.1 — 2026-11-17

=== Corrigé

* Un répertoire de stockage dont un parent n'est pas traversable (ex.
  `/var/backups`, `root:wheel 0750` sous FreeBSD, pour
  `sudo -u postgres`) ne fait plus planter jawas sur une
  `File::AccessDeniedError` non rattrapée. `jawas check` l'affiche en
  contrôle échoué ; `backup`, `prune`, `list`, `verify` et `upload`
  s'arrêtent en code 1 avec un message clair : le chemin, l'utilisateur
  qui lance jawas et le répertoire parent fautif avec son propriétaire et
  ses droits. `receive` renvoie cette raison à l'émetteur.
* Même diagnostic pour `--config`, `password_file` et `recipients_file` :
  `check` compte un `password_file` illisible comme un échec. Un
  emplacement de configuration implicite inaccessible (`~/.config` de
  l'appelant conservé par `sudo`) est passé.
* Filet de sécurité : plus aucune erreur de fichier ou d'entrée-sortie
  ne finit en exception non rattrapée (code 1).

== v0.4.0 — 2026-11-16

=== Ajouté

* Envoi distant `[[remote]]`, enchaîné par `backup --apply` (sauf
  `-N/--no-upload`) ou lancé seul par `jawas upload` (`u`, dry-run sans
  `--apply`, `-r/--remote` pour choisir la destination). Toujours en
  ajout seul : rien n'est jamais supprimé ni remplacé à distance.
* Type `ssh` : récepteur `jawas receive` (`rx`) sur l'hôte distant, en
  commande forcée de la clé de l'émetteur. Seuls les fichiers absents
  sont transmis, l'empreinte SHA-256 est contrôlée à l'arrivée, les
  copies weekly/monthly sont recréées en liens physiques sans
  transfert ; un fichier distant différent est refusé, jamais remplacé.
* Type `rclone` : `rclone copy --immutable` vers tout stockage rclone
  (S3 OVH, Scaleway…), avec `periods` pour n'envoyer que `daily`.
* `-S/--storage` : remplace le répertoire de stockage ; sans fichier
  de configuration, suffit à `receive`, `prune`, `list` et `verify`
  sur l'hôte distant.
* `jawas check` ouvre une session avec chaque récepteur ssh.

=== Modifié

* Une configuration sans `[[source]]` est acceptée (hôte récepteur) ;
  `backup` la refuse.
* Code de sortie 2 aussi en cas d'envoi en échec ; le rapport
  `last-run.json` gagne `uploads`.

== v0.3.0 — 2026-11-16

=== Ajouté

* `jawas verify` (`v`) : contrôle à trois niveaux (empreinte `.sha256`,
  archive déchiffrée et décompressée, contenu complet : marque de fin
  `mysqldump`/`pg_dump`, en-tête `PGDMP`, `COMMIT;` ou
  `PRAGMA integrity_check` SQLite) ; dernière sauvegarde de chaque base
  ou toutes (`-A`) ; code 2 en cas d'échec.
* `jawas restore` (`r`) : dry-run par défaut, base jetable
  `<base>_r<AAAAMMJJHHMM>` par défaut, choix par date (`-D`) ou fichier
  (`-f`), cible (`-t`), écrasement explicite (`-R`) ; MySQL/MariaDB,
  PostgreSQL (SQL et custom), SQLite (remplacement atomique).
* `-i/--identity` : clé privée age pour relire les sauvegardes
  chiffrées.
* Garde-fous : empreinte contrôlée avant chargement, base jetable
  supprimée si la restauration échoue, `_globals` refusé (à rejouer à
  la main), clé manquante détectée dès le dry-run.

=== Modifié

* Erreurs des outils externes résumées aux lignes d'erreur.

== v0.2.0 — 2026-11-16

=== Ajouté

* Chiffrement `age` des sauvegardes (section `[encryption]`) : après la
  compression, vers des clés publiques `age1…`, `ssh-ed25519` ou
  `ssh-rsa` (`recipients`) et/ou un fichier au format `age -R`
  (`recipients_file`) ; `binary = "rage"` possible. Extension `.age`,
  somme `.sha256` du fichier chiffré.
* `jawas check` vérifie que `age` accepte chaque destinataire ; `jawas
  list` signale les sauvegardes chiffrées ; modèle `jawas sample`
  complété.

=== Modifié

* Le flux de sauvegarde chaîne désormais plusieurs filtres (compression
  puis chiffrement) ; en cas d'échec, seul le filtre le plus en aval est
  rapporté (plus de « Broken pipe » trompeur).
* Une clé privée `AGE-SECRET-KEY-…` placée par erreur dans la
  configuration est refusée.

== v0.1.0 — 2026-11-16

=== Ajouté

* Création du shard depuis
  https://github.com/aloli-crystal/shard-template[aloli-crystal/shard-template]
  (réinterprétation Crystal d'automysqlbackup).
* Moteurs MySQL/MariaDB, PostgreSQL (SQL ou `custom`, rôles via
  `_globals`) et SQLite (`.backup` à chaud ou dump SQL).
* Configuration TOML validée (clés inconnues refusées), recherche XDG
  puis `/etc/jawas` ; aucun mot de passe en clair.
* Rotation daily/weekly/monthly par liens physiques, rétention en jours
  avec plancher `keep_min`.
* Compression en flux : none, gzip, pigz, bzip2, xz, zstd.
* Fichiers `.part` + renommage atomique, `.sha256`, permissions
  0600/0700, liens `latest/`.
* CLI `backup`, `prune`, `list`, `check`, `sample`, `help` (raccourcis
  b, p, l, c, s, h), dry-run par défaut et `--apply`.
* Verrou, hooks `pre`/`post`, rapport `last-run.json`, codes de sortie
  0/1/2/3.
